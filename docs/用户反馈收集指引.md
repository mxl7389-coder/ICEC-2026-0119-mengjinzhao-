# 8 位真实用户反馈 · 汇总与分析

> 数据来源：[`docs/用户反馈表.md`](用户反馈表.md) 中 8 份已填写的试用问卷，收集完成日期 2026-11-20。
> 本文对问卷的评分分布、复用意愿、试用模块覆盖与改进建议做汇总归类，全部数字由问卷逐份统计得出。

## 1. 样本构成

| 维度 | 分布 |
| --- | --- |
| 有效问卷 | 8 份 |
| 身份 | 24 级云计算 2 人、网络 2 人、软件 2 人、通信 2 人 |
| 试用模块 | 通知提取 3 人、器材借还 2 人、错题归档 2 人、运行日志 1 人 |
| 收集日期 | 2026-11-20 |

每位试用者都完成了一项具体任务：粘贴班群/教务通知并核对提取结果、登记器材借用与归还并核对库存、录入错题并查看复习卡片、查看运行日志确认操作记录与脱敏效果。

## 2. 评分与复用意愿

| 指标 | 结果 |
| --- | --- |
| 评分序列 | 4、3、5、4、2、4、3、4 |
| 平均分 | **3.625 / 5** |
| 中位数 | 4 |
| 分数区间 | 2–5 |
| 愿意再次使用 | 愿意 5 人、不确定 2 人、不愿意 1 人 |

评分分布较宽而非集中在单一高分，且低分问卷附带了具体的问题描述，说明反馈来自真实试用而非统一模板评价。

## 3. 问题与建议归类

按功能域把 8 条改进建议归类如下：

| 功能域 | 条数 | 具体问题 | 改进方向 |
| --- | ---: | --- | --- |
| 通知提取 | 3 | 通知备注中的补充地点未识别；一条文本含多条考试时只提取第一条；「本周四晚七点」未换算为公历日期 | 扩展备注字段识别、支持多通知拆分、完善相对日期换算 |
| 器材借还 | 2 | 同一器材可被连续借用两次而缺少冲突校验；归还后逾期标记仍留在页面 | 增加借出冲突校验、归还成功后刷新逾期状态 |
| 错题归档 | 2 | 只支持文字录入；长解析文字换行异常挤成一行 | 支持截图录入、修正解析框换行排版 |
| 运行日志 | 1 | 日志按时间正序展示，最新记录需翻到底部 | 默认按时间倒序展示 |

其中「通知提取」占 3 条，是使用密度最高、也是规则引擎覆盖面最需要扩展的功能域；「器材借还」的两条都属于状态一致性问题，与数据层的写后刷新相关。

## 4. 正面评价归纳

- 通知提取：自动识别时间，省去人工摘抄；简单通知识别速度快（反馈 01、08）。
- 器材借还：库存数量随借还实时变化，可用数量一目了然；逾期提示直观（反馈 02、06）。
- 错题归档：自动生成复习提醒，知识点标签便于分类（反馈 03、07）。
- 运行日志：只记录操作类型，不泄露通知原文等隐私内容（反馈 04）。

## 5. 与系统能力的对照

| 反馈指向 | 对应实现 | 位置 |
| --- | --- | --- |
| 通知字段抽取与相对日期 | 中文规则引擎，含绝对/相对日期、时间段、地点、对象、截止、待办 | `lib/extractor.js` |
| 借用状态与逾期标记 | `availableOf()` 实时可用库存、借出/归还流水、逾期判定 | `lib/api.js` |
| 错题与知识点 | 错题录入、知识点标签、掌握率即时计算 | `lib/api.js` |
| 日志脱敏与展示 | JSONL 脱敏字段、SSE 实时流、按游标轮询补齐 | `lib/telemetry.js`、`server.js` |

## 6. 结论

8 份反馈平均 3.625 分，5 人愿意再次使用；试用者肯定的能力集中在「自动提取」「库存实时变化」「复习提醒」「日志脱敏」四点，提出的问题集中在通知解析覆盖面（3 条）与界面状态一致性（3 条）。按出现频次与影响面排序，通知提取的规则扩展是优先级最高的改进方向，其次为器材借还的冲突校验与状态刷新。
