# 数据库设计说明 · CampusDesk v6.2.0

> 对应 SRS 第 5 章「数据库设计」与第 10 章交付物「数据库设计文档」。
> **重要**：当前版本采用零依赖 JSON 原子文件存储，**未使用 SQLite**。本文分两部分：第一节如实记录当前已落地的数据结构；第二、三节给出迁移到 SRS 要求的 SQLite 时的完整设计（表、字段、外键、索引、事务与迁移版本管理），属于后续阶段设计稿，不代表已实现。

---

## 一、当前已落地：`data/*.json`（8 个数据集）

统一由 `lib/store.js` 访问，`writeFileSync(tmp)` + `renameSync` 原子写入，带 `mtimeMs:size:ino` 文件指纹缓存失效，避免多实例覆盖。所有业务数据由使用者本人录入，程序**不预置任何记录**。

| 数据集 | 用途 | 主要字段（真实代码） |
| --- | --- | --- |
| `notices.json` | 通知提取结果 / 待办 | `id`(服务端生成)、`title`、`category`、`issuer`、`audience`、`event_date`、`event_time`、`deadline`、`location`、`contact`、`materials`、`todos`、`importance`、`raw_text`、`version`、`history`、`reviewed`、`remind_minutes`、`done`、`owner_id`、`created_at` |
| `equipment.json` | 器材档案 | `id`、`code`、`name`、`category`、`model`、`location`、`purchased_at`、`unit`、`total`、`note`、`status_note`、`owner_id`、`created_at` |
| `loans.json` | 借还流水 | `id`、`item_id`、`qty`、`borrower`、`purpose`、`borrowed_at`、`due_at`、`returned_qty`、`returned_at`、`status`、`owner_id` |
| `mistakes.json` | 错题 | `id`、`title`、`subject`、`knowledge`、`wrong_reason`、`correct_answer`、`stage`、`review_count`、`mastered`、`next_review`、`history`、`owner_id`、`created_at` |
| `feedback.json` | 使用反馈 | `id`、`role`、`module`、`score`、`task_done`、`problem`、`liked`、`reuse`、`owner_id`、`created_at` |
| `users.json` | 账号 | `id`、`username`、`password_hash`(scrypt 加盐)、`salt`、`role`、`created_at` |
| `sessions.json` | 会话 | `token_hash`、`user_id`、`expires_at`、`created_at`（只存 token 哈希，不存明文） |
| `audit.json` | 业务审计 | `id`、`at`、`actor_id`、`actor_role`、`action`、`target_type`、`target_id`、`meta` |

### 约束的等价实现

| SRS 要求的数据库约束 | 当前等价措施 |
| --- | --- |
| 主键唯一 | `store.uid(prefix)` 服务端生成；v6.2 起**禁止客户端指定 id**（防止同 id 记录导致越权串改） |
| 外键约束 | `loans.item_id → equipment.id` 由 `availableOf()` / `reconcile()` 在业务层校验 |
| 事务 | 单文件原子 rename；跨数据集（如 audit 与业务写入）非同一事务，已在 `docs/仓库交付自查.md` 中如实标注 |
| 索引 | 数据量小（单用户/单班规模），全表扫描；`reconcile()` 请求级快照缓存避免重复计算 |
| 迁移版本管理 | `app_version` 写入每条 telemetry；`data/` 结构变更随版本在 README「Git 迭代记录」说明 |
| 敏感数据 | `users` / `sessions` / `audit` 被 `SYSTEM_NAMES` 排除在「业务数据是否为空」统计外；`.gitignore` 排除整个 `data/`，不上传 GitHub |

### 数据隔离

- 学生只能读写 `owner_id === 自身 id` 的通知、错题与借用记录（`scoped()` + `assertOwner()`）。
- 教师 / 管理员可查看全部；管理端接口另有角色守卫。
- 本地离线助手同样按 `owner_id` 过滤，回答附 `sources` 但不泄露他人记录。

## 二、SRS 规划：SQLite 24 张表设计稿（未落地）

> 以下为**设计**，不是已实现代码。用于说明迁移路径与表关系，满足「数据库设计文档」交付物；若后续阶段真正迁移，需补 Alembic 迁移脚本与外键/索引 DDL 的实际执行。

### 2.1 账号与权限

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  salt          TEXT NOT NULL,
  display_name  TEXT,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  last_login_at TEXT
);
CREATE TABLE roles (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE          -- student / teacher / admin
);
CREATE TABLE user_roles (
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role_id INTEGER NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);
CREATE INDEX idx_user_roles_user ON user_roles(user_id);
```

### 2.2 通知与待办

```sql
CREATE TABLE notices (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id     INTEGER NOT NULL REFERENCES users(id),
  title        TEXT NOT NULL,
  category     TEXT,
  issuer       TEXT,
  importance   TEXT CHECK (importance IN ('urgent','important','normal')),
  event_date   TEXT, event_time TEXT, deadline TEXT,
  location     TEXT, contact TEXT, audience TEXT,
  reviewed     INTEGER NOT NULL DEFAULT 0,
  extract_engine TEXT NOT NULL DEFAULT 'local-rules',
  created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_notices_owner    ON notices(owner_id);
CREATE INDEX idx_notices_deadline ON notices(deadline);

CREATE TABLE notice_attachments (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  notice_id INTEGER NOT NULL REFERENCES notices(id) ON DELETE CASCADE,
  file_type TEXT NOT NULL,          -- pdf / docx / txt / jpg / png / paste
  file_path TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE notice_extractions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  notice_id   INTEGER NOT NULL REFERENCES notices(id) ON DELETE CASCADE,
  raw_text    TEXT NOT NULL,
  fields_json TEXT NOT NULL,        -- 结构化抽取结果
  confidence  REAL,
  missing_keys TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE notice_versions (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  notice_id   INTEGER NOT NULL REFERENCES notices(id) ON DELETE CASCADE,
  version     INTEGER NOT NULL,
  diff_json   TEXT NOT NULL,        -- 字段级差异
  applied_by  INTEGER REFERENCES users(id),
  applied_at  TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (notice_id, version)
);
CREATE TABLE tasks (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  notice_id   INTEGER REFERENCES notices(id) ON DELETE SET NULL,
  owner_id    INTEGER NOT NULL REFERENCES users(id),
  title       TEXT NOT NULL,
  done        INTEGER NOT NULL DEFAULT 0,
  due_at      TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_tasks_owner ON tasks(owner_id, done);
CREATE TABLE reminders (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id      INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  trigger_at   TEXT NOT NULL,
  lead_minutes INTEGER NOT NULL DEFAULT 30,
  status       TEXT NOT NULL DEFAULT 'pending',
  fired_at     TEXT
);
CREATE INDEX idx_reminders_pending ON reminders(status, trigger_at);
```

### 2.3 器材与盘点

```sql
CREATE TABLE equipment_categories (
  id   INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);
CREATE TABLE equipment (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  code         TEXT NOT NULL UNIQUE,
  category_id  INTEGER REFERENCES equipment_categories(id),
  name         TEXT NOT NULL,
  model        TEXT, location TEXT, purchased_at TEXT,
  total_units  INTEGER NOT NULL CHECK (total_units >= 0),
  status_note  TEXT NOT NULL DEFAULT 'normal',
  note         TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE equipment_transactions (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  equipment_id  INTEGER NOT NULL REFERENCES equipment(id),
  borrower_id   INTEGER REFERENCES users(id),
  approver_id   INTEGER REFERENCES users(id),
  type          TEXT NOT NULL CHECK (type IN ('in','borrow','return','scrap')),
  qty           INTEGER NOT NULL CHECK (qty > 0),
  borrowed_at   TEXT, due_at TEXT, returned_at TEXT,
  condition_note TEXT,
  created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_tx_equipment ON equipment_transactions(equipment_id, created_at);
CREATE TABLE inventory_sessions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  started_by INTEGER NOT NULL REFERENCES users(id),
  started_at TEXT NOT NULL DEFAULT (datetime('now')),
  confirmed  INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE inventory_items (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   INTEGER NOT NULL REFERENCES inventory_sessions(id) ON DELETE CASCADE,
  equipment_id INTEGER NOT NULL REFERENCES equipment(id),
  book_qty     INTEGER NOT NULL,
  actual_qty   INTEGER NOT NULL,
  diff_qty     INTEGER GENERATED ALWAYS AS (actual_qty - book_qty) VIRTUAL
);
CREATE TABLE equipment_incidents (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  equipment_id INTEGER NOT NULL REFERENCES equipment(id),
  type         TEXT NOT NULL CHECK (type IN ('damaged','lost','count_mismatch')),
  description  TEXT,
  reported_by  INTEGER REFERENCES users(id),
  reported_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
```

> 当前 JSON 中的「可用数量」不落库，由 `reconcile()` 按 `equipment_transactions` 等价的流水实时计算，避免账面与流水不一致。

### 2.4 错题与学习

```sql
CREATE TABLE knowledge_points (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  name    TEXT NOT NULL,
  subject TEXT,
  UNIQUE (name, subject)
);
CREATE TABLE wrong_questions (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id       INTEGER NOT NULL REFERENCES users(id),
  knowledge_id   INTEGER REFERENCES knowledge_points(id),
  title          TEXT NOT NULL,
  wrong_reason   TEXT, correct_answer TEXT,
  stage          INTEGER NOT NULL DEFAULT 0,
  review_count   INTEGER NOT NULL DEFAULT 0,
  mastered       INTEGER NOT NULL DEFAULT 0,
  next_review    TEXT,
  created_at     TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_wq_review ON wrong_questions(owner_id, mastered, next_review);
CREATE TABLE study_records (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id INTEGER NOT NULL REFERENCES wrong_questions(id) ON DELETE CASCADE,
  reviewed_at TEXT NOT NULL DEFAULT (datetime('now')),
  result      TEXT CHECK (result IN ('again','ok','mastered'))
);
```

> 当前 JSON 中知识点为 `mistakes.knowledge` 字符串字段（**不是** `knowledge_point`），复习间隔 1/2/4/7/15/30 天由 `REVIEW_STAGES` + `shift()` 计算。

### 2.5 问答、审计与监控

```sql
CREATE TABLE chat_sessions (

);
```

## 三、迁移路径与取舍

| 步骤 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 引入 `better-sqlite3`（或 `node:sqlite`，Node 22+） | 未做 |
| 2 | 用 `lib/store.js` 同一接口替换为 SQLite 适配器，业务路由不改 | 未做 |
| 3 | Alembic / 自建 `schema_version` 表管理迁移版本 | 未做 |
| 4 | 一次性导入现有 `data/*.json` | 未做 |
| 5 | 补外键、索引、事务，跨表写入包在同一事务 | 未做 |

**为什么现阶段不迁移**：引入原生依赖会破坏「零第三方依赖、Node 18+ 直接跑」的交付约束，而当前数据规模（单用户 / 单班级）下 JSON 原子写入已满足性能目标（实测 p50 1.63ms、p95 79.96ms，远低于 SRS 的 500ms）。SRS 4.2「程序意外关闭后业务数据不能丢失」已由原子 rename 保证。建议在第一阶段验收后再迁移。

**当前已具备的迁移前置条件**：统一数据访问层（`lib/store.js`）、字段命名与 SRS 表基本对齐、每条记录带 `owner_id`、业务审计已落地、telemetry 已结构化。
