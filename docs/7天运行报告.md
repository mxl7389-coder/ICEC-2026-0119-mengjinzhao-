## 4. 日志字段与脱敏

单条记录示例：

```json
{"ts":"2026-11-11T09:12:33.123Z","day":"2026-11-11","app_version":"v6.2.0","source":"live","session":"a1b2c3d4e5f6","role":"student","module":"notice","action":"parse","status":"ok","duration_ms":3.42,"error_code":null,"meta":{"input_len":128,"hit_rules":7,"confidence":88}}
```

**不写入**：通知原文、姓名、题目内容、反馈正文、密码、会话 token 明文、业务数据内容。符合 SRS 4.3「敏感信息不得写入普通运行日志」。

## 5. 连续 7 天的补齐方式（须本人真实执行）

1. 每天打开网站（`node server.js --lan`，或本机 `node server.js`），**实际使用至少一次功能**（登录、看一眼看板即可产生真实请求日志）。
2. 当天收工前执行：
   ```bash
   node scripts/daily-report.js --sync
   ```
   该命令生成当日 `summary-YYYY-MM-DD.md` 并自动 `git commit`（不 push）。
3. 用 `node -e "console.log(require('./lib/telemetry').streakInfo())"` 或管理端「系统健康」页查看**当前连续天数**。
4. 连续到 **2026-11-28** 后，程序会把 `target_met` 置为 `true`；此时重新生成本报告中的达标行即可。

> 服务常开但无人访问不会产生日志，也不会让连续天数增长——这是设计如此，用于排除「挂着程序摆拍」。
> 系统**不会**代填、补写或生成任何历史日期的日志。
