# 使用说明 · 校园事务台 CampusDesk

> 这一版有登录、有学生/教师工作台、有管理员实时日志后台。**所有数据都由你和使用者自己录入，程序不预置任何内容。**

---

## 一、启动

在 `E:\校园软件` 目录下执行：

```bash
node server.js
```

终端会打印实际地址，例如 `→ http://localhost:5174`（5173 被占用时自动顺延）。浏览器打开该地址即可，根路径会自动判断该去哪个页面。

停止服务：在终端按 `Ctrl+C`。

---

## 二、第一次打开：由你创建管理员

首次启动时 `data/users.json` 为空，页面会显示 **「创建管理员账号」**（这个界面只出现一次）：

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 会显示在右上角，如「张老师」 |
| 管理员账号 | 3–24 位，中文 / 字母 / 数字 / `_ . -` |
| 密码 | 至少 8 位，必须同时含字母和数字 |
| 确认密码 | 再输一次 |

提交后自动登录并跳转到 `/admin.html` 管理后台。**这个账号由你本人设置，系统里没有任何默认账号或演示用户。**

---

## 三、创建学生 / 教师账号

在管理后台左侧点 **「账号管理」**：

1. 填写登录账号、显示名称、选择角色（学生 / 教师 / 管理员）、设置初始密码；
2. 点「创建账号」；
3. 把账号和初始密码**线下告知本人**，让对方登录后在工作台右上角「修改密码」里改掉。

账号列表里可以「停用 / 启用」和「重置密码」。停用或重置后，该账号已有的其它登录会话会立即失效。

角色能做什么：

| 角色 | 权限 |
| --- | --- |
| 学生 | 录入并查看**自己**的通知与错题、登记器材借出/归还、提交反馈 |
| 教师 | 学生全部能力 + 查看全部通知与错题、新增/删除器材、查看反馈汇总 |
| 管理员 | 实时日志、日志分析、账号管理、数据总览（也能从后台进入工作台） |

权限在服务端二次校验，学生即使直接访问 `/admin.html` 也会被送回工作台。

## 四、日常使用（学生 / 教师工作台 `/index.html`）

| 页面 | 怎么用 |
| --- | --- |
| 总览看板 | 待处理通知、逾期未还、今日待复习、反馈进度一目了然 |
| 通知提取 | 粘贴**你自己的**通知原文 → 「结构化提取」→ 核对结果 → 「保存到待办」；也可导出 `.ics` 日历或复制 Markdown |
| 器材借还 | 先由教师/管理员在「新增器材」录入清单，之后任何人都能登记借出、部分归还、全部归还，系统自动算库存与逾期 |
| 错题归档 | 录入题目摘要、学科、知识点、错因，按 1/2/4/7/15/30 天排队复习 |
| 使用反馈 | 真实试用后填写；目标 8 位真实同学，系统不会代填 |

> 第一次进去所有列表都是空的，这是**刻意设计**：数据要由你和使用者录入。每个空状态都写明了下一步该做什么。

## 五、管理员后台 `/admin.html`

| 页面 | 内容 |
| --- | --- |
| **实时运行日志** | SSE 长连接，服务端每次写日志就推送一条，无需刷新。可按模块、状态、关键字筛选，可暂停刷新、清空显示。断线自动重连，重连期间用 2 秒轮询补齐 |
| 日志分析 | 按模块调用频次、错误码分布、最近报错、按日期查看历史明细；一键生成当日日报 |
| 账号管理 | 创建 / 停用 / 启用 / 重置密码 |
| 数据总览 | 各数据集条数、服务运行状态、角色分布；**只看条数，不展示业务内容** |

日志里只有时间、角色、模块、动作、状态、耗时、错误码和脱敏特征（长度、条数等），**不含**通知原文、姓名、学号、题目、反馈正文、账号或密码。

## 六、累计作业要求的 7 天日志

每天正常使用后，睡前执行一次：

```bash
node scripts/daily-report.js --sync   # 生成当日日报 + 自动 git commit（不 push）
git push                              # 需要提交到 GitHub 时再执行
```

日志按自然日写入 `process_logs/YYYY-MM-DD.jsonl`。连续使用 7 天后，目录里自然就有 7 个日期文件 + 7 份日报。**程序不会补造历史日志**，这正是作业「防摆拍」的要求。

## 七、常见问题

**Q：忘记管理员密码怎么办？**
没有内置后门。可以让另一位管理员在后台重置；如果只有一个管理员且忘了密码，需要删除本机 `data/users.json`（会清空所有账号，业务数据不受影响）后重新初始化。请先备份该文件。

**Q：学生看不到器材？**
器材清单初始为空，需要教师或管理员先在「器材借还 → 新增器材」录入。学生账号没有新增器材的权限。

**Q：学生登录后看不到别人的通知/错题？**
这是设计如此：学生只看自己录入的记录，教师和管理员看全部。

**Q：后台的实时日志不动？**
先看右上角状态：绿色「实时连接」表示 SSE 正常；橙色「轮询补齐」表示 SSE 暂断，正在用 2 秒轮询兜底。随便在另一个标签页点一下工作台功能，就会立刻产生新日志。

**Q：怎么确认没有预置数据？**
打开管理后台 → 「数据总览」，业务数据集条数应全为 0；或查看 `data/*.json`，内容都应为 `[]`。

## 八、验证命令

```bash
node scripts/smoke-test.js   # 50 项断言，独立端口 5199 + 隔离数据目录，跑完自动清理
```

冒烟测试会创建临时的管理员/学生/教师账号和测试记录，但**只写在 `data/__smoke__/` 并在结束时删除**，不会往你的日常数据里加任何东西。产生的运行日志是真实请求记录。
