## 一、启动与三套入口

在 `E:\校园软件` 目录下执行：

```bash
node server.js
```

终端会打印实际地址，例如 `→ http://localhost:5174`（5173 被占用时自动顺延）。

| 入口 | 地址 | 谁用 | 说明 |
| --- | --- | --- | --- |
| 动态封面 | `/` | 所有人 | 中国书院 × 校园文化的动画首屏，两个独立入口卡片；会显示当前登录状态与时间问候 |
| 用户端 | `/user/` | 学生 / 教师 | 独立登录页（浅色书院风）+ 工作台 |
| 管理端 | `/admin/` | 管理员 | 独立登录页（深墨蓝控制台）+ 首次创建管理员 + 实时日志后台 |

两套系统**登录后互不跳转、界面上不出现对方入口**；服务端还会按入口校验角色，管理员账号不能从用户端登录，学生/教师账号不能从管理端登录。旧链接 `/login.html`、`/index.html`、`/admin.html` 会自动跳转到新入口。

停止服务：在终端按 `Ctrl+C`。

## 二、重新注册：由你创建第一位管理员

当前 `data/users.json` 为空，打开封面会看到管理端卡片标注「待创建管理员」。点「管理员 · 进入管理后台」→ 管理端登录页显示 **「创建管理员账号」**（只在管理端出现、只出现一次）：

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 会显示在右上角，如「张老师」 |
| 管理员账号 | 3–24 位，中文 / 字母 / 数字 / `_ . -` |
| 密码 | 至少 8 位，必须同时含字母和数字 |
| 确认密码 | 再输一次 |

提交后自动登录并进入 `/admin/` 后台。**这个账号由你本人设置，系统里没有任何默认账号或演示用户。**
用户端 `/user/` 在初始化完成前不会开放登录，会提示先由管理员完成设置。

## 三、创建学生 / 教师账号

在管理后台左侧点 **「账号管理」**：

1. 填写登录账号、显示名称、选择角色（学生 / 教师 / 管理员）、设置初始密码；
2. 点「创建账号」；
3. 把账号和初始密码**线下告知本人**，让对方从 `/user/` 登录后在工作台右上角「修改密码」里改掉。

账号列表里可以「停用 / 启用」和「重置密码」。停用或重置后，该账号已有的其它登录会话会立即失效。

角色能做什么：

| 角色 | 权限 |
| --- | --- |
| 学生 | 录入并查看**自己**的通知与错题、登记器材借出/归还、提交反馈 |
| 教师 | 学生全部能力 + 查看全部通知与错题、新增/删除器材、查看反馈汇总 |
| 管理员 | 实时日志、日志分析、账号管理、数据总览（只从 `/admin/` 进入） |

权限在服务端二次校验，学生即使直接访问 `/admin/index.html` 也会被送回管理端登录页；管理员访问 `/user/index.html` 同样会被挡回。

## 四、日常使用（学生 / 教师工作台 `/user/`）

| 页面 | 怎么用 |
| --- | --- |
| **总览看板** | 对齐 SRS `CM-FR-001` 的七项指标：今日待办、即将到期通知、未归还借用、器材库存、近 7 天调用、软件运行状态、最近操作记录；顶部状态条显示版本、运行时长、内存与日志天数 |
| **通知与任务** | 四步流程：导入**你自己的**通知原文（手动粘贴 / `.txt` / `.md` / `.csv` / `.json`，可拖放）→ 结构化提取（含发布单位、联系方式、所需材料、重要程度）→ **人工审核**（可校正标题与截止日期、勾选确认、也可拒绝）→ 生成待办。v6.1 增加重复通知识别（只返回相似度，不泄露他人原文）、新旧通知版本比对（字段差异先预览再确认写入 v2）、自定义提前提醒（写入 `.ics` 的 `VALARM`，填 `0` 表示不提醒）；支持按标题 / 类别 / 状态检索 |
| **实验器材** | 教师 / 管理员先录入器材档案（编号、型号、位置、购买日期、备注）；任何人可登记借出、部分归还、全部归还，系统自动算可用库存与逾期 |
| **错题归档** | 录入题目摘要、学科、知识点、错因，按 1/2/4/7/15/30 天排队复习；新增按学科的知识点掌握率统计 |
| **智能助手** | 如实说明当前能力边界：本地规则引擎已上线，本地大模型 / OCR / RAG 问答尚未接入。**此页不提供空壳输入框** |
| **我的足迹** | 只显示当前账号的脱敏调用摘要（时间、模块、动作、状态、耗时、错误码），数据来自真实运行日志 |
| **使用反馈** | 真实试用后填写，字段与 [`用户反馈表.md`](用户反馈表.md) 的 8 份问卷对齐：实际完成的任务、评分、最有帮助的地方、遇到的问题、建议、是否愿意再用；页面显示 `已收 N/8`，目标 8 位真实同学，系统不会代填 |
| **项目与功能地图** | 把 SRS 的 `CM-FR-xxx` 编号与实现状态逐项对照，明确标注「已实现 / 部分实现 / 规划中」 |

> 第一次进去所有列表都是空的，这是**刻意设计**：数据要由你和使用者录入。每个空状态都写明了下一步该做什么。
>
> **重要**：v6.1 起支持 **5 种文本导入方式**（手动粘贴、`.txt`、`.md`、`.csv`、`.json`），文件在浏览器里用原生 `FileReader` 本地解析、可直接拖放，不上传服务器、不依赖任何第三方库；SRS 中的 PDF / Word / 图片导入、本地 OCR、本地大模型问答仍属后续阶段，在「功能地图」如实标注「规划中」，不提供空壳按钮。

## 五、管理员后台 `/admin/`

| 页面 | 内容 |
| --- | --- |
| **实时运行日志** | SSE 长连接，服务端每次写日志就推送一条，无需刷新。可按模块、状态、关键字筛选，可暂停 / 清空 / 跳转导出。断线自动重连，重连期间用 2 秒轮询补齐 |
| **系统健康** | `CM-FR-509` 六项健康检查（服务、数据目录、当日日志、7 天覆盖、错误率、SSE 订阅）+ 实时内存与运行时长，全部由进程当前状态计算；v6.1 起「7 天覆盖」按**当前连续天数**判定，并标明日志来源目录 |
| **日志分析** | 按模块 / 动作 / 角色 / 错误码聚合，最近报错、按日期查看历史明细；一键生成当日日报 |
| **账号与角色** | 创建 / 停用 / 启用 / 重置密码，附三角色权限矩阵（与服务端 `PERMISSIONS` 一致） |
| **数据总览** | 各数据集条数、服务信息、角色分布；**只看条数，不展示业务内容**；v6.1 增加业务审计表（谁 / 何时 / 动作 / 对象 ID，不含原文） |
| **反馈收集** | v6.1 新增：`已收 N/8` 槽位进度与反馈明细，字段与 8 份问卷一致；不代填、不伪造 |
| **备份与导出** | `CM-FR-507` 按自然日导出 JSON / CSV 日志（真实下载）；v6.1 起支持**业务数据快照导出 / 校验 / 恢复**（见下方备份说明）；附日报文件清单 |
| **版本与规划** | 实时读取 `git log` 的迭代时间线 + SRS 2.4 管理员职责对照，AI 模型管理等未实现项标注「规划中」 |

日志里只有时间、角色、模块、动作、状态、耗时、错误码和脱敏特征（长度、条数等），**不含**通知原文、姓名、学号、题目、反馈正文、账号或密码。导出接口同样要求管理员会话，不能匿名下载。

> **备份说明（v6.1）**：「数据总览 / 备份」页可导出带 SHA256 校验和的业务数据快照（自己保存到本机），也可把快照贴回去做**完整性校验**；校验不通过会明确拒绝恢复。恢复必须勾选显式确认，且只恢复通知、器材、借还、错题、反馈等业务数据，**不覆盖账号与会话**。程序不会自动在磁盘上生成副本。

## 六、累计作业要求的 7 天日志

每天正常使用后，睡前执行一次：

```bash
node scripts/daily-report.js --sync   # 生成当日日报 + 自动 git commit（不 push）
git push                              # 需要提交到 GitHub 时再执行
```

日志按自然日写入 `process_logs/YYYY-MM-DD.jsonl`。连续使用 7 天后，目录里自然就有 7 个日期文件 + 7 份日报。**程序不会补造历史日志**，这正是作业「防摆拍」的要求。

**v6.1 的两处口径修正**：

- 日报新增「连续运行达标自检」，按**当前连续天数**（不是累计天数）判定，并列出断档明细、历史最长连续与达标日期；系统健康页、总览看板同步显示 `连续 x / 7 天`。日报是生成时刻的**静态快照**，此后新产生的访问不会回写，次日或收工前重新运行会覆盖为最新口径。
- 日志新增 `source` 字段：`live`（真实使用）、`legacy`（v6.1 前的历史记录，错误率含测试噪声）、`smoke`（测试，写入 `process_logs/__smoke__/` 且跑完即删）。冒烟测试不再把故意触发的报错混进真实 telemetry。

> ⚠️ **当前实际状态**：累计 5 天（11-11、12、13、16、17），11-14 / 15 断档，**当前连续仅 2 天**；需从 11-16 起连续真实使用到 **11-22** 才达标。

## 七、常见问题

**Q：为什么封面和两端界面看起来完全不一样？**
这是刻意的分离：封面是共享的校园文化主视觉，用户端浅色宣纸风、管理端深墨蓝控制台，各自有独立登录页。封面动画为纯 CSS + 内联 SVG，不加载任何外部图片或字体；系统开启「减少动态效果」时会自动关闭动画。

**Q：在哪里查询已注册的账号？**
两个地方：① 管理员登录 `/admin/` → 左侧「**账号管理**」→ 账号列表（显示登录账号、角色、显示名称、状态、创建时间）；② 本机文件 `data/users.json`，或在项目目录执行 `node scripts/reset-password.js` 直接列出全部账号。后者不需要登录，适合忘了管理员密码时用。

**Q：在哪里查询密码？查得到吗？**
**查不到，这是刻意的安全设计。** 密码用 scrypt 加盐哈希后保存（`salt` + `password_hash`），不可逆，系统里任何页面、日志、`data/users.json` 都不存明文，连开发者也无法还原。日志同样不记录密码或任何凭据。如果确实需要，只能**重置**，不能查看。

**Q：忘记密码怎么办？**
- 知道旧密码：用户端工作台右上角「修改密码」自己改。
- 管理员还在登录：`/admin/` → 「账号管理」→ 该账号「重置密码」，填新密码即可（不需要知道旧密码）。
- **连唯一的管理员密码也忘了**：在项目目录执行
  ```bash
  node scripts/reset-password.js                 # 先列出账号，确认账号名
  node scripts/reset-password.js --reset 你的账号   # 交互式输入新密码（推荐，密码不进命令历史）
  ```
  也可以 `node scripts/reset-password.js --reset 账号 新密码` 直接指定，但明文会留在终端历史里。重置后该账号原有会话全部失效，用新密码重新登录即可。此工具只认「能读写本机 `data/` 目录」这一权限，不提供网页后门。

**Q：提示「当前登录的账号与本入口不匹配」？**
说明同一浏览器里已经登录了另一端的账号。可以直接用本端账号登录（会切换会话），或先到原入口退出登录。这是入口隔离的正常表现。

**Q：打开又让我「创建管理员账号」，我明明注册过了？**
如果确实已注册过，通常是本机开了多个服务实例、或手工改过 `data/users.json`，旧进程的内存缓存没跟上（v4.0.1 起已改为按文件指纹自动刷新缓存）。先重启服务，再执行 `node scripts/reset-password.js` 确认账号还在；**不要在「创建管理员账号」页面重复提交**。
但**当前是正常情况**：2026-11-16 已按你的要求清空了全部账号，现在本来就该重新创建管理员。

**Q：学生看不到器材？**
器材清单初始为空，需要教师或管理员先在「器材借还 → 新增器材」录入。学生账号没有新增器材的权限。

**Q：学生登录后看不到别人的通知/错题？**
这是设计如此：学生只看自己录入的记录，教师和管理员看全部。

**Q：后台的实时日志不动？**
先看右上角状态：绿色「实时连接」表示 SSE 正常；橙色「轮询补齐」表示 SSE 暂断，正在用 2 秒轮询兜底。随便在另一个标签页点一下工作台功能，就会立刻产生新日志。

**Q：怎么确认没有预置数据？**
打开管理后台 → 「数据总览」，业务数据集条数应全为 0；或查看 `data/*.json`，内容都应为 `[]`。

**Q：导入文件会上传到服务器吗？支持哪些格式？**
不会。`.txt` / `.md` / `.csv` / `.json` 由浏览器原生 `FileReader` 在你本机读成文本，再按普通粘贴文本走同一套解析接口；可直接拖到导入区。PDF / Word / 图片需要 OCR 与对应解析库，尚未实现，页面标注「规划中」。CSV 会取文本列拼接，JSON 会尝试读取常见文本字段，解析结果一律以人工审核为准。

**Q：备份恢复会覆盖我的账号吗？**
不会。恢复只覆盖通知、器材、借还、错题、反馈等业务数据，`users` / `sessions` 不参与。快照带 SHA256 校验和，被改动过会校验失败并拒绝恢复；恢复前必须勾选显式确认。

**Q：提示「请求来源与本站不一致，已拒绝」？**
这是 v6.1 加的同源校验，防止别的网页替你提交写请求。正常从本站页面操作不会触发；若用脚本或代理访问导致 `Origin` / `Referer` 与 `Host` 不一致，请从服务实际打印的地址打开页面再操作。
