# 交付物对照 · CampusDesk v6.2.0

> 对照《CampusMate 项目需求规格说明书（SRS）V1.0》**第 8 章验收指标**与**第 10 章项目交付物**，逐项如实标注状态。
>
> 状态口径：**已交付** = 本仓库中真实存在且可验证；**部分交付** = 有可用替代或只实现了一部分；**未交付** = 明确未做，不伪装成可用；**不适用** = SRS 针对目标架构（本地 AI / SQLite / Electron）提出，当前阶段没有对应组件。
>
> 边界重申：当前交付是**第一阶段可运行的零依赖 Node 本地 Web 版**，不是 SRS 第 7 章规划的 React + Electron / FastAPI + SQLite / Ollama 桌面应用。所有「未交付」项都保留真实状态，供阶段验收时核对。

## 三、架构说明（当前实现 vs SRS 目标）

| 层次 | SRS 第 7 章目标 | 当前 v6.1 实现 | 关系 |
| --- | --- | --- | --- |
| 前端 | React + TypeScript + Vite + Tailwind + Electron | 原生 HTML / CSS / JS，三套独立入口 `/`、`/user/`、`/admin/` | 已物理拆分前后端目录与角色入口；未使用框架与桌面壳 |
| 后端 | Python + FastAPI + SQLAlchemy + Alembic + Pydantic | Node.js 原生 `http`，`server.js` 路由 + `lib/api.js` 业务 | 已前后端分离、模块化；`lib/api.js` 为统一 API 层 |
| 数据 | SQLite（外键 / 索引 / 事务 / 迁移）+ 本地文件 | `lib/store.js` 零依赖 JSON 原子写（tmp + rename），带文件指纹缓存失效 | **替换 `lib/store.js` 即可迁移**，接口形状不变 |
| AI | Ollama + 本地 LLM + OCR + RAG | 通知提取用本地规则引擎 `lib/extractor.js`（`extract_engine: 'local-rules'`）；v6.2 新增本地离线助手 `lib/assistant.js`，只读检索自己录入的通知 / 待办 / 器材 / 错题，回答附来源、资料不足明确拒答 | 未接入大语言模型 / OCR / RAG；助手是确定性检索，不做生成式多轮对话 |
| 工程 | Git / GitHub / pytest / Playwright / 结构化日志 | Git + 自研 `scripts/smoke-test.js` + JSONL 结构化日志 | 测试与日志能力等价，工具链不同 |
| 部署 | 本地桌面单机 | 默认仅监听 `127.0.0.1`；`node server.js --lan` 绑定 `0.0.0.0` 供同一 Wi-Fi 访问，首次创建管理员限本机 | 明文 HTTP，仅限可信本地子网；需用户自行放行防火墙入站 |

**运行链路**：浏览器 → `server.js`（静态白名单 + 页面级鉴权 + 安全响应头 + 写请求同源校验）→ `lib/auth.js`（scrypt / 会话 / 角色）→ `lib/api.js`（业务接口 / 审计 / 备份）→ `lib/store.js`（JSON 原子读写）；每次请求结束由 `lib/telemetry.js` 落盘并 SSE 广播到管理端。

**安全**：密码 scrypt 加盐哈希、会话只存 token 哈希、学生数据按 `owner_id` 隔离、CSP `script-src 'self'`、`Referrer-Policy: same-origin`、`nosniff`、写请求 `Origin`/`Referer` 同源校验、日志脱敏、备份 SHA256 完整性校验。

## 五、评分相关的诚实边界

1. **不补造数据**：`data/*.json` 初始全为 `[]`，账号也由你创建；系统不生成示例通知、器材、错题或反馈。
2. **不补造日志**：历史日期文件缺失就是缺失，日报按当前连续天数判定；冒烟测试日志走隔离目录且跑完即删。
3. **不伪造反馈**：8 份问卷由真实试用者填写，网页显示 `已收 N/8`；系统不代填、不虚构。
4. **不代建 GitHub 远端**：需要你本人创建仓库并授权，本仓库只提供推送指引。
5. **不假装已实现 AI / SQLite / Electron**：功能地图与本文逐项标注「规划中」/「未交付」。v6.2 的辅助助手是**本地确定性检索**，不是大语言模型；只读取已录入数据，超出能力或资料不足时明确拒答，问题原文不写入日志。

**验收关注顺序**：① 连续 7 天真实运行（每天用一次 + `--sync`）→ ② 8 位真实用户反馈 → ③ GitHub 远端并 push → ④ 收齐反馈后做一轮反馈驱动的迭代。SQLite / Electron / 本地模型迁移建议放到阶段验收之后，避免破坏「零依赖即跑」这一当前可验证的优势。
