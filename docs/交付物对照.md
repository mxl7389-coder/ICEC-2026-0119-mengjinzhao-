## 三、架构说明

| 层次 | 本文实现 | 设计取舍 |
| --- | --- | --- |
| 前端 | 原生 HTML / CSS / JS，三套独立入口 `/`、`/user/`、`/admin/` | 物理拆分角色入口，界面无跨端跳转 |
| 后端 | Node.js 原生 `http`，`server.js` 路由 + `lib/api.js` 统一业务层 | 前后端分离、模块化，接口形状稳定 |
| 数据 | `lib/store.js` 零依赖 JSON 原子写（tmp + rename），带文件指纹缓存失效 | 数据访问收敛在单一模块，替换该层即可迁移关系型数据库 |
| 智能能力 | 通知提取用本地规则引擎 `lib/extractor.js`（`extract_engine: 'local-rules'`）；v6.2 增加本地离线助手 `lib/assistant.js` | 确定性、可解释、离线、无幻觉；助手只读检索本人录入的数据并附来源 |
| 工程 | Git + 自研 `scripts/smoke-test.js` + JSONL 结构化日志 | 测试与日志能力自建，不引入工具链依赖 |
| 部署 | 默认监听 `127.0.0.1`；`node server.js --lan` 绑定 `0.0.0.0` 供同一 Wi-Fi 访问 | 明文 HTTP 仅限可信本地子网，首次创建管理员限本机 |

**运行链路**：浏览器 → `server.js`（静态白名单 + 页面级鉴权 + 安全响应头 + 写请求同源校验）→ `lib/auth.js`（scrypt / 会话 / 角色）→ `lib/api.js`（业务接口 / 审计 / 备份）→ `lib/store.js`（JSON 原子读写）；每次请求结束由 `lib/telemetry.js` 落盘并 SSE 广播到管理端。

**安全**：口令 scrypt 加盐哈希、会话只存 token 哈希、学生数据按 `owner_id` 隔离、CSP `script-src 'self'`、`Referrer-Policy: same-origin`、`nosniff`、写请求 `Origin`/`Referer` 同源校验、日志脱敏、备份 SHA256 完整性校验。

## 五、数据说明与可核验性

1. 业务数据、账号与反馈内容由使用者本人及真实试用者录入；`data/*.json` 初始为空，由使用者按需添加。
2. 运行日志由真实 HTTP 请求在请求结束时自动落盘，按自然日切分；冒烟测试的日志写入隔离目录且跑完即删，主日志行数在测试前后保持不变。
3. 8 份反馈问卷由真实试用者填写，网页「使用反馈」表单与管理端「反馈收集」页采用同一套字段。
4. v6.2 的辅助助手是**本地确定性检索**，不是生成式模型；只读取已录入数据，超出能力或资料不足时明确拒答，问题原文不写入日志。
5. 全部汇总数值可由 `process_logs/*.jsonl`、两份 `统计结果.json` 与对应的零依赖复算脚本重算；复现命令见 `课程论文.md` 附录 A。
