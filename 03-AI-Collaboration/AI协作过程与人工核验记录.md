## 1. 协作定位

AI 在本项目中承担三类工作，**不替代**真实运行、真实用户与本人判断：

| 角色 | 具体做什么 | 不做什么 |
| --- | --- | --- |
| 问题定位助手 | 读日志、读代码、复现异常、解释原因、给出候选改法 | 不替程序"承诺"未实现的能力 |
| 文档与结构整理 | 按 SRS 编号整理功能地图、对照表、交付物清单 | 不虚构需求、不把规划写成已交付 |
| 教学与排障陪跑 | 解释 Git / 终端 / 报错含义，给出可复现命令 | 不代填反馈、不补造日志、不代建他人名下的账号资产 |

## 3. 提示策略（可复用）

从本项目实际有效的提问中归纳出的四类写法：

1. **给证据，不给猜测**：把日志行、报错原文、代码行号一起贴出来，而不是只说"功能坏了"。
   > 例：「`process_logs/2026-11-11.jsonl` 里 parse 的 `confidence` 只有 63，原文是……，请逐字段说明哪里没匹配上。」
2. **要求可复现**：让结论附带一个最小复现步骤或隔离验证命令，便于自己再跑一遍。
   > 例：「请在临时目录起一个隔离实例验证这个 URL 会不会让进程退出，不要动正在运行的服务。」
3. **要求区分「已实现 / 规划中」**：明确禁止把未实现能力写成可用按钮或已交付文档。
4. **要求不代填真实数据**：明确禁止生成示例反馈、补写历史日志、虚构访谈记录。

## 4. 人工核验清单（每次 AI 改动后本人执行）

- [ ] `node --check` 全部 JS 语法通过
- [ ] `node scripts/smoke-test.js` 全量断言通过，且失败项被真实修复而非删除断言
- [ ] 隔离目录（`data/__smoke__/`、`process_logs/__smoke__/`）跑完已清理
- [ ] 主日志行数在测试前后不变，无 `smoke` 来源记录
- [ ] 真实浏览器打开三套入口，未登录 / 越权拦截符合预期
- [ ] 业务数据未新增任何记录（保持「一切数据由我添加」）
- [ ] 文档中的版本号、测试数量、状态标签与代码一致
- [ ] 未达标项（连续 7 天、8 位反馈）如实标注，不美化

## 5. 边界：AI 明确不做的事

| 不做 | 原因 |
| --- | --- |
| 补造缺失日期的 telemetry 日志 | 日志由真实 HTTP 请求自动写入，补写即伪造运行记录，违背题目「防摆拍」 |
| 代填 8 位真实用户反馈 | 反馈须由真实使用者试用后填写，系统只提供空白模板与收集指引 |
| 虚构阶段一访谈对象、照片、`raw_data/` | 属真实调研证据，只能本人采集 |
| 把 OCR / 本地大模型 / RAG / SQLite 标为「已实现」 | 当前未接入，功能地图一律标「规划中」 |
| 用他人账号创建仓库或代管凭据 | 仓库与凭据归账号所有者本人 |
