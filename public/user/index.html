为什么先做规则引擎

SRS 1.3 要求「人工确认：AI 生成的信息不得未经确认直接执行重要业务操作」、4.2 要求「AI 服务不可用时不影响基础业务功能」。当前实现把通知提取做成完全离线的确定性规则，即使在无模型、无网络、模型服务崩溃的情况下，通知待办、器材核对、错题复习三项核心业务依然可用；后续接入本地模型时，只需在 lib/extractor.js 之外增加一层可回退的模型适配器，不改动现有数据流。

技术架构差异说明

SRS 第 7 章规划的是 React + Electron 桌面客户端、Python FastAPI + SQLite 后端与 Ollama 本地模型。当前交付为第一阶段可运行版本：零依赖 Node.js 本地 Web 服务 + JSON 原子存储 + 纯本地中文规则引擎，保留了前后端分离、模块化 lib/、统一数据访问、自动 Telemetry 与 Git 迭代记录这些架构约束。迁移到 SQLite 时只需替换 lib/store.js，业务接口与页面无需重写。

隐私说明

日志里不写通知原文、姓名、学号、题目内容与反馈正文，只保留长度、条数、命中规则数、耗时、状态码、错误码、角色等可统计特征；会话标识为不可逆哈希，密码以 scrypt 加盐哈希保存。业务数据仅保存在本机 data/，是否同步到 GitHub 由你决定（.gitignore 默认排除 data/，只提交日志）。
