# 通知结构化抽取 · Prompt 模板

> 这是一份**可直接复制使用**的 Prompt，属于课题 10 要求交付的「AI 脚本 / Prompt」。
> 使用时把它和一条样本内容一起发给大模型；模板正文、字段顺序与六条规则见下方，可直接复制。

## 模板正文（复制以下全部内容）

```
你是校园通知结构化助手。下面给你一条班群或教务通知原文，请把它抽取成一行结构化记录。

输出字段（严格按此顺序，用 JSON 对象输出，不要输出解释文字）：
{
  "事项": "",
  "日期": "",
  "时间": "",
  "地点": "",
  "截止日期": ""
}

规则：
1. 只使用原文中明确出现的信息。原文没写的字段一律填「未提及」，不要推测、不要补全、不要用常识补日期。
2. 区分「通知发布日」「活动发生日」「报名截止日」；有多个日期时，把活动发生日填入「日期」，报名截止日填入「截止日期」。
3. 日期统一写成 YYYY-MM-DD；原文写「本周五」「下周一」等相对时间时，原样保留并加后缀「（相对时间，需人工确认）」。
4. 时间统一写成 HH:MM-HH:MM；只有开始时间就写「HH:MM-未提及」。
5. 地点保留原文写法，不要扩写或标准化。
6. 事项用不超过 20 个字概括，不要添加原文没有的修饰。

通知原文：
<<<在这里粘贴一条通知原文>>>
```

## 为什么这样写

| 设计 | 对应的人机校验风险 |
| --- | --- |
| 强制 JSON、禁止解释文字 | 便于粘贴进表格，减少格式返工 |
| 「未提及」而非空白字段 | 避免模型自行脑补造成「视觉/文本幻觉」 |
| 区分三类日期 | 通知里最容易抽错的字段 |
| 相对时间加后缀 | 把需要外部信息才能判断的项显式标出来，交给人工复核 |
| 地点不标准化 | 避免模型把「三教 431」擅自改成别的写法 |

## 使用注意

- 每次只发**一条**样本，10 条分别计时，不要一次打包 10 条（否则无法按样本记耗时）。
- 全程用同一个模型、同一份 Prompt；中途改动要在 CSV 的「使用的Prompt文件」列写明用的是哪一版。
- 本仓库不含任何大模型调用代码、API Key 或联网逻辑；你用的是自己账号下的大模型网页/客户端，原始通知不要粘贴到不可信的第三方服务。
