> **性质声明**：本文是基于**课程题干列出的真实痛点**与**本程序实际实现**整理的分析说明，不是访谈记录、问卷统计或现场调研原始材料。功能映射与代码位置可在仓库源码中逐项核对。

## 1. 选题

**项目四：解决校园真实痛点的轻量化实用程序研发与日常运行日志验证**

选择在个人电脑上运行的「校园事务台 CampusDesk」，把学生日常最高频、最琐碎、最容易遗漏的三件事收进同一个本地工具。

## 2. 痛点来源与场景

题干列出的校园真实问题：

| # | 痛点 | 具体场景 | 后果 |
| --- | --- | --- | --- |
| 1 | 通知分散在不同渠道，重要信息容易遗漏 | 班群、教务网、辅导员通知、社团群各自发布 | 错过报名 / 缴费 / 考试截止 |
| 2 | 通知长、手动整理截止时间地点任务效率低 | 一段几百字通知里夹着时间、地点、对象、材料 | 反复回看原文，仍漏项 |
| 3 | 实验室器材借还、盘点依赖人工登记 | 纸质表格或群消息登记借出 | 账实不符、找不到责任人 |
| 4 | 数量不准，逾期、损坏、账实不符 | 借出后未登记归还，库存数字不更新 | "账上有、柜里没有" |
| 5 | 错题整理与知识点归纳耗时 | 手抄题目、抄完不再看 | 同类错误反复出现 |
| 6 | 校园信息缺少统一查询入口 | 想知道"最近截止是什么"要翻多个群 | 时间浪费、信息焦虑 |

## 4. 为什么采用「本地优先 + 零依赖」

1. **数据不出本机**：通知内容、错题、账号全部留在 `data/`，不上传云端，符合 SRS 4.3 与校园隐私常识。
2. **断网可用**：无 API Key、无 CDN、无在线模型，宿舍断网或校园网故障时基础业务不受影响（SRS 4.2）。
3. **零安装门槛**：Node 18+ 直接 `node server.js`，无需 `npm install`、无需构建、无需数据库服务，便于同学真实试用并收集反馈。
4. **可验证**：每次请求自动写脱敏日志，能真实反映"用了几天、哪里出错、为什么迭代"，正好对应项目四的防摆拍要求。

## 5. 设计原则在代码中的体现

| 题干 / SRS 原则 | 落地方式 |
| --- | --- |
| 人工确认优先 | 通知提取结果必须人工核对后才入库；版本变更差异先预览再确认 |
| 重要操作可追溯 | `data/audit.json` 记录动作、角色、对象 id；不写原文 |
| 数据安全 | scrypt 加盐哈希、角色权限、归属隔离、备份 SHA256 校验 |
| 稳定运行 | JSON 原子写入、畸形输入兜底、SSE 断线游标补齐 |
